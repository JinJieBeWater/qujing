# Qujing v0.2.0

Qujing 使用单个 daemon 承载本地 Agent MCP 和 Peer-facing Node MCP，新增 TanStack ACP Runtime，同时保留内置 Pi RPC。

## 主要变化

- `qj init` 同时初始化 Node 和本地 MCP；`qj serve` 启动完整服务；`qj doctor` 汇总诊断。
- `runtime set-acp` 支持自定义 ACP CLI，持久化消息、运行记录和 ACP session ID。
- 统一 Node、Peer、Peer Link 术语与命令，移除 gateway/client 角色参数。
- 加固 Runtime 取消、启动中断清理、Connector 回收及服务异常退出恢复。
- Tailcat 建连设置单次尝试上限；已接受的 ask 不重试。
- JSON 文件读取采用有界并发；参数解析、端口诊断及 reload 等待使用共享实现。

## 从 v0.1.x 升级

这是不兼容升级。旧配置不会自动迁移；不要直接运行新版本，也不要用 `qj init` 覆盖已有配置。

1. 记录现有版本、服务、Runtime、Workspace、调用方 MCP 和已配对设备。在当前用户专属目录备份 Qujing 配置、状态、旧二进制及服务定义；备份包含凭据，目录使用 `0700`、文件使用 `0600`。
2. 使用**旧版二进制**移除已安装服务：`qj service remove gateway --yes`、`qj service remove client --yes`。未安装的角色无需操作。前台进程需单独停止；确认旧进程退出后再迁移。
3. 配套升级 `qj` 与 `qujing-transport`。保留旧版本用于回退；暂不启动新服务。
4. 在备份副本上完成以下字段迁移并按新版本 Schema 校验，再原子替换活动文件。保留所有 ID、时间戳、Workspace 根目录、Tailcat 密钥和 bearer 值；目标字段已存在或值冲突时停止，人工核对。

| 旧数据                                             | v0.2.0                                 |
| -------------------------------------------------- | -------------------------------------- |
| `config.json` 的 `owner`、`clients`                | `node`、`peers`                        |
| `tombstones.json` 的 `clients`                     | `peers`                                |
| `runtime-sessions/*.json` 的 `clientId`            | `peerId`；文件名及 session ID 保持不变 |
| `client.json`                                      | `agent.json`；`lines` 改为 `peers`     |
| 每条旧 Line 的 `expectedOwnerId`、`remoteClientId` | `expectedNodeId`、`remoteAgentId`      |

配置/状态默认目录见 README；自定义 XDG 或 Windows 目录按原安装位置处理。旧 client 进程锁、reload 确认等临时控制文件不作为新 Agent 的运行状态迁入。密钥路径保持原值，不能随目录改名而失效。

5. 显式配置 Runtime：Pi 使用 `qj runtime set-pi --model <provider/model>`，或用 `runtime set-acp` 配置 ACP CLI。Pi 0.85.1 已验证；0.84.3 缺少取消所需的 `clear_queue`。不改变宿主 Pi 默认配置、认证、扩展和历史归档。
6. 没有旧 `client.json` 时，按 `AgentConfig` Schema 单独创建私密 `agent.json`：`version: 1`、loopback `server`（默认端口 43111）、空 `peers` 和新生成 bearer 的 SHA-256 `localBearerHash`。bearer 使用加密安全随机源生成，原文只写入调用方私密 MCP 配置，不放入日志或工单。不要在已有 Workspace 或 Runtime 的 Node 上再次运行 `qj init`，该命令会拒绝不同的现有配置。
7. 运行 `qj service install --yes` 与 `qj doctor`。macOS 新服务为 `com.qujing.daemon`，Linux 为 `qujing.service`。调用方连接本地 `/mcp`，仅发现 `list_peers` 和 `ask`；远端配对双方需使用兼容版本再验证请求。

升级失败时，先停止新 daemon，再恢复旧二进制、配置和状态快照，最后恢复旧服务。不要让两版同时写同一份状态。Qujing Runtime binding 与 Pi 原生会话都必须保留。

## 验收范围

macOS Apple Silicon 和 Linux x64 为目标平台。Windows x64 仍为 Preview，尚未完成 Windows 原生验收。已有设备证据和未覆盖范围见 [验收记录](../acceptance/2026-09-07-three-devices-single-daemon.md)。
